## 2. Privacy

- The app never asks for a name or a contact. Free text a guest types is redacted for emails and phone numbers (international, national and Gambian formats) before anything is stored, once ingest exists.
- Noor's monthly text is a checked template filled with counts and checked theme labels, and nothing else.
- The outbox schema is strict: an unknown field is rejected, so no personal field can ride along.
- Audio of people's voices is never in git (the repository is public). Teammates get it privately; `content/ondera-noor/recordings/audio.sha256` lets them verify the files.
- Guest questions and feedback are redacted (`redact()`) before they go into the on-device outbox (`apps/web/src/lib/ask.test.ts` :: `redacts emails and phone numbers, tags a device theme and keeps the farm id`; `apps/web/src/components/guest/shop-feedback.test.tsx` :: `redacts an email and a phone number the guest typed, before anything is stored`). A safety question is not stored at all.
- The QR scanner reads the camera on the phone only: no frame is stored or uploaded, and the e2e watcher fails on any request that leaves the page.
- Noor's farm code is in the pack only as a salted PBKDF2 hash, never as the code itself (`apps/web/src/lib/order-feedback.test.ts` :: `the pack holds a salted hash and the demo code appears nowhere in the manifest`).
- The 116 test questions contain no personal data (a test redacts them and expects no change).

## 4. Human oversight

What exists today: the `checks.json` mechanism and the pack gating. **By design, not built:** Noor's held report and reviewer approval. The guest's confirm card and the order sheet (`Noor confirms your payment in person.`) are built in the guest app; the order is stored only after Noor types her 4-digit farm code (`apps/web/src/components/guest/shop-feedback.test.tsx` :: `stores nothing when the guest orders; the order is stored only after Noor enters her farm code`; `apps/web/src/components/guest/shop-feedback.test.tsx` :: `a wrong code stores nothing and says so; three wrong codes lock the form for 30 seconds`; `packages/core/test/farm-code.test.ts` :: `accepts the right code and rejects every wrong one`). **The farm code is a prototype control**: the pack holds a salted PBKDF2 hash (never the code), but a 4-digit code has 10,000 values, so someone with the pack can find it offline; it stops a guest tapping the button, not an attacker. The real confirmation belongs on Noor's own device or the dashboard.

- **Checks:** nothing is checked until a person signs an entry in `checks.json` (who, when). A subtitle check is bound to the exact text it approved: new or regenerated text makes it a draft again.
- **The guest decides:** the phone shows a topic label and the guest confirms before anything plays; below the threshold the question is saved for Noor.
- **Noor's text:** held until a Wolof speaker checks the template and a reviewer approves (to be built).
- **Orders:** counted only after Noor confirms payment in person: the schema requires `confirmedByNoor`, and the guest app stores an order only after Noor enters her 4-digit farm code (a prototype control, see row 6).

## 5. Honest trade-offs

- **The threshold.** `docs/EVAL.md` reports the numbers on held-out halves of the questions, with intervals; they are wide, and one fold alone can be far from the pooled figure. The shipped threshold is the strictest of the picks for the demo and the production pack, which trades coverage for caution. A false confirmation shows a wrong card the guest can reject; it never plays unconfirmed.
- **Synthetic questions.** Written by the team, not by guests; de, nl and sv unchecked. Real guests will differ.
- **Machine drafts and non-commercial models.** NLLB and MMS are CC-BY-NC; their output is labeled and never shipped to production unchecked.
- **Wolof.** Machine translation and speech recognition for Wolof were measured on small samples (`docs/EVAL.md`). The round trip on the 8 AI-dubbed clips is low, so the dubbed Wolof is **unverified**: it may be poor Wolof, or MMS may struggle with synthetic speech, and the numbers cannot say which. A Wolof speaker has to check before anything reaches Noor.
- **A stand-in voice.** Preet's voice stands in for Noor's, disclosed on screen in every language. It is honest but it is not Noor.
- **Index-only passages:** 93 unchecked question-style phrasings that are never displayed but affect which clip is offered. The captain decided on 2026-10-04 (recorded in `tasks/todo.md`) that they may ship in production, labeled `indexOnly` in the manifest; that is in tension with rule 5 and is flagged here on purpose. The guest still confirms every match. They were written without the test questions by an isolated assistant and audited against them (`docs/EVAL.md`), but the same model family wrote the questions, so the measured gain may be optimistic.
- **The farm code is a prototype control.** A 4-digit code has 10,000 values, so anyone who holds the pack can find it offline (PBKDF2 slows that down, it does not stop it), and the 30-second lockout lives in page memory. It stops a guest tapping the button; it is not strong authentication. Orders should be confirmed on Noor's own device or the dashboard. The demo and fixture code `4827` is a documented prototype value (`tasks/HANDOFF.md`), never a real farm's code, and a production pack built without `ASKNOOR_FARM_CODE` cannot confirm any order.
- **The offline test runs on a synthetic pack in desktop Chromium** with a Pixel 7 profile. Real phones and iOS Safari are untested, and the matcher's first load time on a phone is not measured.
- **A smaller model, with a cost.** The trimmed vocabulary keeps the same held-out top-1 but splits rare words differently from the full model (`content/ondera-noor/eval/trim-fidelity.json`: 0.52 of held-out English lines tokenize identically).
- **Dropped parts.** To fit two SMS segments the monthly text can drop its least important parts; the reviewer must see which.
- **Different CPUs, slightly different vectors.** The threshold has not been checked against phone-made vectors.
